# Shared library

Reusable OpenSCAD building blocks. Projects live in `projects/<name>/`, so they reach these files as
`../../lib/...`. Each module documents its coordinate convention at the top of the file.

| File | Use with | What it gives you |
|---|---|---|
| `core.scad` | `include` in projects, `use` in lib files | atoms everything else builds on: `pick()` part selector, `slab(z1, z2)`, `affine2d(m)`, `mirror_pair()`, `csk_hole()` countersunk screw hole, `stroke_2d()` / `border_2d()` outlines, `sum()`, `polar()`, `qbez()`, `circle3()`, and the `COL_*` colour palette for `parts` tables |
| `fits.scad` | `include` | ISO 286 fits: `fit_mid("H7", d)` for holes, `fit_mid("p6"/"k6"/"g6", d)` for shafts |
| `fonts.scad` | `use` | registers the bundled fonts (see `fonts/README.md`); `font_for("serif" / "serif bold" / "sans" / "sans bold" / "book serif bold" / "round sans bold")`; text metrics for letter-by-letter layout: `font_adv()`, `font_em()`, `font_cap()`, `text_len()`, `size_for_cap()` (tables in `fonts_metrics.scad`, generated by `tools/font_metrics.py`) |
| `shapes.scad` | `use` | `plaque_2d(size, shape)` outlines: rect, rounded, chamfered, notched, arched, wave, scalloped. `profiled_slab(t, profile, r)` routed top edge: flat, roundover, chamfer, cove, ogee. `profiled_slab2()` profiles on top and bottom edges. `outline_groove()` single/double decorative groove. `has_edge_wave(shape)`. |

| `shell.scad` | `use` | thin walls that follow a closed outline (boxes, baskets, bins, lamp shades): outlines `shell_rect_runs()` (round / chamfer / square corners, named runs), `shell_ellipse_pts()`, `shell_squircle_pts()`, `shell_wavy_pts()`; measuring `shell_len()`, `shell_dists()`, `shell_bounds()`; rim height field `shell_rim_height()` and `shell_rim_dip()` (grip cut-out); `shell_dist_at()`; `shell_strip_pts()` (the unrolled wall with its top edge) and `shell_wrap()` which bends a flat panel round the outline. See [Shells](#shells) |
| `container.scad` | `use` | the parts of an open box on a shell outline: `container_walls()` / `container_wall()` (patterned walls bent round the outline, with framed openings), `container_floor()` (with holes), `container_ledge()` (45° ledge for an inset lid), `container_ridge()` (rounded saddle on the floor with sloped ends and a domed top: nose support, bottle or cable rest), mounting built into the back wall for the attachment plates: `container_mount()` spec, `container_mount_problem()`, `container_plates()`, pattern-free `plain` areas; helpers `container_u()` / `container_v()` (place an opening on a wall from plan coordinates), `container_safe_mode()`. Each style module also defines its option list (`PLAQUE_SHAPES`, `EDGE_PROFILES`, `MARKER_STYLES`…),
so a model can copy them into its `// [a, b, c]` Customizer comment.

## Conventions

- **Layers:** `core.scad` (atoms) → element files (`shapes`, `rail`, `scale`, `attach`, `led`, `cable`, `emblem`, `patterns`, `shell`, `container`) →
  data (`emblems/`, `fonts/`) → projects. Element files may `use <core.scad>` but not each other, except where one
  clearly builds on another. Projects never copy library code: if something is missing, add it here.
- **Naming:** 2D generators end in `_2d`, point-list functions in `_pts`, cutters say so in their comment, private
  helpers start with `_`. Style choices are string parameters with an upper-case option list beside them.
- **Frames:** every file states its coordinate convention in its header (where the origin is, which face is z=0).
  Host cutters (`attach_socket`, `cable_route`, `led_recess`) take the host's back face as z=0 with the body at z>0.
- **One spec, many parts:** parts that must fit each other take the same spec value (`rail`, `led_spec`, attachment
  `size`), so they cannot drift apart.
- **Fits:** clearances are constants at the top of the file (`ATTACH_CLR`, `LED_CLR`…); snap parts must bend 2% or less.
- **After changing a lib file:** run `python3 tools/build.py all --test`. Every project lists its variants in `tests.txt`.

## Example

```scad
use <../../lib/shapes.scad>
use <../../lib/rail.scad>

    rail_slider(rail, style="arrow");
    for (x=[-85, 85]) translate([x, 0, rail_h(rail)]) stop_peg(style="ball", shaft_l=8);
}
```

## Patterns

`patterns.scad` makes decorative and structural patterns a building block for any flat surface: walls, floors,
roofs, lids, panels, inserts. A project picks a pattern by name, sets a few numbers and says how to apply it.
The catalogue and test bench is `projects/pattern_gallery`.

Three layers, kept apart:

| Layer | Modules | Job |
|---|---|---|
| 1. pattern engine | `pattern_2d()`, `pattern_3d()` (generators in `patterns/`) | the bare pattern, tiled, rotated, clipped |
| 2. surface application | `pattern_cutout_2d()`, `pattern_panel_2d()`, `pattern_relief()`, `pattern_cutter()`, `pattern_lining()`, `pattern_panel(mode)` | cut through, raise, engrave, open lattice, lining |
| 3. project geometry | your project | place the result with `translate()` / `rotate()` |

### Frame

Every module works in the XY plane, centred on the origin, inside the rectangle `size = [x, y]`. The decorated
surface is the plane z = 0 and its outside is +Z:

| Module | Z range |
|---|---|
| `pattern_2d` | 2D |
| `pattern_3d`, `pattern_relief` | stands on z = 0, rises to z = h (relief starts 0.01 below, to fuse with the host) |
| `pattern_cutter` | z = 0 down to z = −depth: subtract it from a host whose surface is z = 0 |
| `pattern_lining` | lies on z = 0, `t` thick (plus `depth` when raised) |
| `pattern_panel` | slab z = 0..t, decorated face on top; relief and linings above t |

For a vertical wall, a sloped roof or any other flat face, build in this frame and then move the result, e.g.
`rotate([90, 0, 0])` for a wall facing −Y. The **child** of a module is the surface outline (any 2D shape inside
`size`); without a child the outline is the rectangle `size`. The pattern is anchored at the origin (a cell centre
or a strand lies on it), so a larger `size` adds cells around the same centre and neighbouring panels cut from
the same spec line up when their origins are a whole number of cells apart.

### The 12 patterns

`PATTERNS` lists the names. `cell` is the repeat size and `strut` the width of the material; an opening is
about `cell − strut` wide. Pattern-specific settings go into `opts=[["key", value], ...]`.

| Name | What it is | `cell` (default) | `strut` (default) | `opts` (default) |
|---|---|---|---|---|
| `hex_honeycomb` | connected honeycomb ribs | centre-to-centre distance (12) | rib width (1.5) | `orient`: "pointy" / "flat" |
| `square_grid` | orthogonal ribs | pitch, or [x, y] (10) | rib width, or [vertical, horizontal] (1.5) | `stagger` 0..0.5: shift of every other row (0) |
| `diamond_lattice` | diagonal ribs | [diamond width, height] ([12, 18]) | rib width (1.5) | – |
| `triangular_lattice` | three rib families, triangular openings | triangle side (14) | rib width (1.5) | `alternate` (true; false opens every other triangle), `orient`: "up" / "side" |
| `basket_weave` | plain over-under weave of strips, real 3D | strip pitch (10) | strip width (7; = cell for a closed weave) | `lift` in mm (0.375 × h), `style`: "flat" / "rounded" |
| `tri_weave` | three-direction cane weave (kagome), real 3D | distance between parallel strands (24) | strand width (3; must be under cell/3) | `lift`, `style` |
| `voronoi` | irregular cell network | average cell size (14) | wall width (1.5) | `irregularity` 0..1 (1), `round` corner radius (0), `min_cell` fill cells smaller than this (0); uses `seed` |
| `fish_scales` | overlapping scales, tip down | [scale width, height] ([12, 12]) | line width of the scale edges (0.8) | `overlap` (0.4), `curvature` 0.2..1 (0.7), `stagger` (0.5), `shingle` (true: raised as stepped scales), `steps` (3) |
| `truchet_arcs` | quarter-ring tiles that join into paths | tile size (12) | arc width (1.6) | `variation`: "random" / "alternate" / "rows" / "uniform", `bias` (0.5); uses `seed` |
| `girih_star_cross` | eight-point stars touching at their tips, crosses between | repeat spacing (24) | strap width (1.6) | `star` diameter (= cell; smaller adds straight straps between the tips), `star_ratio` (0.765) |
| `flowing_waves` | parallel sine ribs | rib pitch (8) | rib width (2.4) | `amplitude` (3), `wavelength` (30), `phase` (0°), `shift` per rib (0°), `ties` (bars between ribs every n wavelengths; automatic when cut through) |
| `concentric_ripples` | rings around one or more centres | ring spacing (6) | ring width (2) | `rings` (0 = fill), `first` radius, `centers` ([[0, 0]]), `spokes` (radial ties; automatic 6 when cut through), `falloff` 0..0.9 (0), `steps` (4) |

Common settings of a spec, for every pattern:

```scad
p = pattern_spec(name, cell, strut,
                 angle=0,            // rotation of the pattern (degrees)
                 offset=[0, 0],      // shift (phase), in the pattern's own axes
                 density=1,          // >1 = more, smaller cells (pitch = cell/density, strut unchanged)
                 seed=1,             // voronoi, truchet_arcs: same seed = same pattern
                 scale=[1, 1],       // stretch of the finished pattern (ribs stretch too)
                 opts=[],            // pattern-specific settings
                 min_strut=0.8, min_opening=1);     // printability limits (0 = no check)
```

Every module takes a spec or just a name; with a name you can pass `cell`, `strut`, `angle`, `seed` and `opts`
directly: `pattern_2d("voronoi", [100, 80], cell=10, seed=7)`.

### Applying a pattern

| You want | Use | Notes |
|---|---|---|
| the pattern as a 2D shape | `pattern_2d(p, size)` | material (ribs / lines); combine with `linear_extrude`, `difference`, `intersection`, `union` |
| the pattern as a solid | `pattern_3d(p, size, h)` | weaves as real strands, fish scales as shingles, ripples with falloff, others extruded; `profile="round"` rounds rib tops |
| holes through a wall | `pattern_cutout_2d(p, size, inset=3)` in a 2D `difference()`, or `pattern_cutter(p, size, depth, pad=3, cut="cells")` in 3D | `cut="cells"` removes the openings, `"lines"` the pattern itself |
| an open framework | `pattern_panel_2d(p, size, border=3)` then extrude, or `pattern_panel("open_lattice", ...)` | frame `border` wide all round; `border=0` when the host provides the frame |
| a raised pattern | `pattern_relief(p, size, h, pad=2)` | add it at the surface |
| an engraved pattern | `pattern_cutter(p, size, depth)` | subtract it at the surface |
| a lining / overlay | `pattern_lining(p, size, t=0.6, mode, depth, inset, border, edge)` | separate skin on the surface: `"through_cut"` (perforated), `"raised"`, `"recessed"`; `edge="chamfer"` |
| a whole panel in one call | `pattern_panel(mode, p, size, t, depth, border, pad)` | `PATTERN_MODES`: solid, through_cut, open_lattice, raised, recessed, overlay |

```scad
use <../../lib/patterns.scad>

// standalone pattern
linear_extrude(1) pattern_2d("hex_honeycomb", [100, 80], cell=12, strut=1.5, angle=15);

// cut-out in a 2D outline, then extrude: a wall with real openings
linear_extrude(2) difference() {
    wall_outline_2d();
    pattern_cutout_2d("hex_honeycomb", [100, 80], cell=12, strut=1.5, inset=4) wall_outline_2d();
}

// raised and engraved on an existing solid (surface at z = 0, body below)
host();
pattern_relief("flowing_waves", [100, 80], h=0.8, pad=3, profile="round");
difference() { host(); pattern_cutter("truchet_arcs", [100, 80], depth=0.6, pad=3); }

// open lattice panel in any outline, woven or not
pattern_panel("open_lattice", "tri_weave", [100, 80], t=2.4, border=3) circle(d=80);

// lining on a wall: 0.6 mm perforated skin, 1.5 mm from the edge, with its own 1.5 mm frame
wall();
pattern_lining("girih_star_cross", [100, 80], t=0.6, mode="through_cut", inset=1.5, border=1.5);

// independent wall, floor and roof
wall  = pattern_spec("basket_weave", cell=10, strut=7);
floor = pattern_spec("concentric_ripples", opts=[["falloff", 0.5]]);
roof  = pattern_spec("hex_honeycomb", cell=12);
pattern_panel("raised", floor, [70, 50], t=3, depth=0.8);
translate([0, -25, 20]) rotate([90, 0, 0]) translate([0, 0, -2]) pattern_panel("open_lattice", wall, [70, 40], t=2, border=3);
translate([0, 0, 40]) pattern_panel("through_cut", roof, [70, 50], t=2, border=3);
```

### Frames, windows and generator centres

- **Frame widths:** wherever a module takes `border`, `pad` or `inset` for the pattern area, a list
  `[sides, bottom, top]` (or `[x, y]`) gives different widths. The list form shifts the outline instead of
  offsetting it, so a wavy or sloped top edge keeps a band of constant height.
- **Windows:** set `$pat_window = [[cx, cy], [w, h]]` around any module to build only that part of the surface.
  The piece is exactly what the full pattern, panel or lining has there (frames are still worked out on the whole
  outline), so pieces built side by side join up. `shell.scad` uses this to go round corners; you can use it to
  split a large panel into printable tiles:

  ```scad
  for (i=[0:1]) translate([i*5, 0, 0]) { $pat_window = [[-50 + i*100, 0], [100, 120]];
      pattern_panel("open_lattice", "voronoi", [200, 120], t=2.4, border=3); }
  ```
- **Generators** (`lib/patterns/*.scad`) take `center=[x, y]`: the point, in the pattern's own axes, around which
  they cover `size`. The pattern stays anchored at the origin, so any window shows the same pattern.

### Printability

- `pattern_problem(p)` returns "" or a sentence saying what is wrong; every module asserts it. Limits are the spec's
  `min_strut` and `min_opening`. Dimensions are never changed for you. `pattern_features(p)` gives
  [rib width, smallest opening].
- Lattices are cut from one plate, so they are always one network and join the frame of any outline. Openings cut
  off by the edge that would be narrower than `min_opening` stay closed instead of leaving slivers.
- Keep a `border` (frame) on open lattices and through-cuts. With `border=0` the rib ends at the edge are free and a
  small fragment can come loose: use it only where the host itself closes the edge.
- **Ties.** Line patterns have no cross connections of their own: cut through, flowing waves would be long
  unsupported bridges and ripples loose rings. So wherever the cells are cut out (`through_cut`, `open_lattice`,
  perforated linings, `pattern_cutout_2d`), `pattern_tied(p)` is applied: waves get a bar between neighbouring ribs
  every wavelength, placed where the ribs come closest (or alternately on crests and in troughs when they run
  parallel, like brick bonds), and ripples get 6 spokes. Set `["ties", n]` / `["spokes", n]` yourself to choose,
  or 0 to switch them off. Reliefs and engravings are not changed.
- `pattern_is_connected(p)` is false for Truchet arcs and for ripples with `spokes` set to 0: those would fall
  apart when cut through, so `through_cut` and `open_lattice` refuse them.
- Weaves stand on z = 0 and need no supports. `lift` must stay at or below 85% of the strand thickness
  (`WEAVE_MIN_FUSE`), so crossing strands share material; total height h = strand thickness + lift.
- Reliefs and linings overlap their host by 0.01 mm so the union is one clean solid.

### Limits

- Desktop OpenSCAD 2021 (CGAL) needs about 15–40 s for a 100 mm woven panel, more with `style="rounded"`; 2D
  patterns take a second or two. Newer OpenSCAD (Manifold) and the browser configurator are much faster.
- Voronoi is the Voronoi diagram of one random site per grid square. Cell sizes spread around `cell`; there is no
  relaxation, so high irregularity gives some slim cells (`min_cell` fills the small ones in).
- `scale` stretches rib widths along with the pattern. Rounded rib tops, fish-scale shingles and ripple falloff
  are built in steps (3–4 levels), which is what a printer makes of a slope at these heights anyway.
- Patterns are planar: a curved wall needs flat facets, each with its own panel.

## Shells

`shell.scad` builds thin walls along any closed outline and lets the wall's top edge follow a height field.
Together with `patterns.scad` this gives patterned boxes, baskets, bins and shades (`projects/custombox`).

- **Outline:** a closed, counter-clockwise list of [x, y] points in the floor plane (z = 0). It is the wall's
  OUTER face. `shell_rect_runs(size, corner, r, fn, side_n)` returns a box as named runs ("front", "corner_fr",
  "right", … ) so walls and corners can be treated separately: `shell_runs_pts()` gives the points,
  `shell_runs_edges()` the edge range of each run. `shell_ellipse_pts()`, `shell_squircle_pts()` and
  `shell_wavy_pts(pts, amp, count)` give round and flowing outlines.
- **Rim:** any `function (p) -> height`; `shell_rim_height(p, size, base, rise, waves, phase)` is a ready-made
  one with a slope in x and y plus cosine waves. Because it depends on the position in plan, it is continuous
  on every outline.
- **Strip frame:** the child of `shell_wrap()` builds the wall flat: x = distance along the outline (0 in the
  middle of the strip), y = height (0 at mid-height `h/2`), z = 0 inner face .. t outer face, relief beyond.
  That is the pattern frame with `size = [strip length, h]`. `shell_strip_pts(pts, e0, e1, hf, h)` is the
  strip's outline with the rim as its top edge.
- **Wrapping:** `shell_wrap(pts, t, e0, e1, h, above)` places one flat facet per outline edge and sets
  `$pat_window` for it; facets overlap at the joints (more at inward bends), so the wall is one solid. Make
  straight runs ONE long edge (fast) and curves short edges. Other 2D content in the child needs
  `shell_window_2d()` to clip it to the facet.

```scad
use <../../lib/shell.scad>
use <../../lib/patterns.scad>
size = [120, 90]; t = 2.4; H = 70;
runs = shell_rect_runs(size, "round", 16, fn=6, side_n=2);
pts  = shell_start_at(shell_runs_pts(runs), shell_run(shell_runs_edges(runs), "back")[1] + 1);   // seam at the back
rim  = function(p) shell_rim_height(p, size, 40, rise=[0, 22], waves=[[4, 2], [0, 1]]);            // sloped, wavy rim
L = shell_len(pts);
shell_wrap(pts, t, h=H)
    pattern_panel("through_cut", "hex_honeycomb", [L + 1, H], t=t, border=[0, 4, 4])
        polygon(shell_strip_pts(pts, hf=rim, h=H));
linear_extrude(2) polygon(pts);                                                                    // floor
```

Joints: a facet reaches `SHELL_LAP` (0.1 mm) past each joint, and every other facet is pulled in and set back by
`SHELL_SHRINK` (0.04 mm). Without that hair of difference, the identical cut-outs of two neighbouring facets almost
coincide where they overlap, which leaves slivers and edge-touching faces in the exported mesh. For the same
reason keep other solids (a floor, a ledge) a hair inside the outline rather than exactly on it.

Limits: walls are vertical (no taper); curved parts are faceted; relief leaves hairline gaps between facets at
outward corners; woven patterns wrapped over many facets are slow in OpenSCAD 2021 (minutes), fine on flat walls.

## Containers

`container.scad` puts shells, patterns and attachment plates together into the parts every box-like project
needs (`projects/custombox`, `projects/earbuds`, `projects/sunglasses`). Front is −Y, back is +Y, the floor's
underside is z = 0.

```scad
use <../../lib/shell.scad>
use <../../lib/patterns.scad>
use <../../lib/container.scad>
size = [64, 36]; t = 2; H = 40;
runs = shell_rect_runs(size, "round", 8, 4);
pts  = shell_runs_pts(runs);
rim  = function(p) H - shell_rim_dip(p, size, depth=14, width=26);          // grip cut-out in the front rim
p    = pattern_spec("hex_honeycomb", cell=7, strut=1.2);

container_floor(pts, 3, p, "solid") translate([0, 2]) circle(d=14);         // floor with a cable hole (plan)
container_walls(pts, t, H, rim, p, "through_cut", bands=[5, 3])             // walls; one opening in the back wall:
    translate([container_u(pts, [0, size[1]/2]), container_v(12, H)]) circle(d=10);
// solid corners, every side its own panel:  container_walls(..., runs=shell_runs_edges(runs), post_w=3)
// mounting:  m = container_mount(pts, "skadis", "S", 1, rim, t, [5, 3], floor_t);  container_walls(..., mount=m);
//             container_floor(..., mount=m);  container_attach(part, m, attach_opts(), 0, H, attach_joint);
```

- **Openings** are 2D children: for walls in the loop's unrolled frame (x from `container_u(pts, plan_point)`,
  y from `container_v(z, h)`), for the floor in plan. Each gets a plain collar `frame` wide. They are cut in 2D,
  so they cost nothing.
- **Seam:** with one panel all round, start the outline where no opening is (`shell_start_at`); an opening must
  not straddle the two ends of the strip.
- **Mounting** is part of the wall, not a plate behind it. `m = container_mount(pts, type, size, count, hf, t,
  [bottom band, rim band])` describes it; pass `mount=m` to `container_walls()` / `container_wall()` and the back
  wall (the straight wall at the largest y) gets a solid zone there: the pattern stops at it and joins its sides,
  the wall is thickened outwards to 6 mm only in the zone, and the sockets are cut into it. A zone that starts
  above the floor has a 45° underside (prints upright without support); if the rim band or the base band is
  closer than 10 mm, the solid area runs on into it and follows a sloped or wavy rim. Plates close together share one
  zone; further apart each gets its own and the pattern continues between them. `container_mount_problem(m)`
  returns "" or the reason it does not fit (assert it); `container_attach(part, m, opts, z_bottom, z_top, joint)`
  draws all attachment parts; `each container_attach_rows(type, m, joint)` goes into the parts table. The back wall
  must be one straight edge. A type that mounts underneath (`fin`) gets the same treatment in the floor: pass
  `mount=m` to `container_floor()` too, and the zone is thickened upwards with the sockets opening downwards.
- **Plain areas:** `plain=[[x, z, w, h], ...]` (centre x in the loop frame, bottom z, size) keeps rectangles of the
  wall free of pattern and solid, e.g. for a label; the pattern joins their edges.
- **Pattern anchor:** `anchor=[x, y]` (a plan point on a wall) centres the pattern there when one panel runs all round.

## Attachment plates

One socket, many plates. The host cuts `attach_socket(size)` into its back face (z=0, body at z>0). Push a plate
straight in and it snaps: two flexible arms at each end (1.2 mm thick, bending 0.6 mm on the way in, under 1%
strain) carry bumps with a 45° lead-in that click into grooves in the socket's end walls. The plate's solid
corners carry the load, so hanging or standing cannot unsnap it. To remove a plate, put a flat screwdriver in the
notch below it and lever it out. Keep plate features out of the end strips (`attach_strip()`) where the arms are.

| Type | Mounts to | Notes |
|---|---|---|
| wall | wall, with 2 countersunk wood screws (Ø4.5, head 8.5) | screw the plate to the wall, then hang the host on it |
| keyhole | a screw or nail head in the wall | head up to Ø9 × 2 mm |
| roof | a ceiling: stem up behind the host to a flange with 4 countersunk screws; `roof_angle` 45–135° (90 = hangs straight down) | the stem keeps 0.6 mm off the snap arms; set `roof_reach` above the host's top edge |
| skadis | IKEA Skådis pegboard | hooks 4.6 mm wide for 5 × 15 mm slots in a 5 mm board; M/L plates have two hooks 40 mm apart. Hosts with several plates keep them on the 40 mm grid. Community-measured sizes, not IKEA's: check against your board. |
| hook | a rod, rail, wire shelf or door of thickness `hook_gap` | |
| magnet | steel surfaces | pockets for round magnets (default 10 × 3), glued in from the wall side |
| stand | a table | two fins make a kickstand; `stand_reach` = plate centre to the host's bottom edge |
| flat | glue or double-sided tape | grooved back for a better bond |
| slide | a dovetail track with rounded edges, screwed to the wall (part `attach_track`) | `slide_axis` "horizontal": the channel runs through the plate, one long track carries all plates and the host can be slid along it; "vertical": the host is dropped onto a short track per plate and hangs on its upper end. `track_len` (0 = automatic). The host stands 5 mm off the wall. |
| fin | a blade that anchors the host from below, e.g. between two sofa cushions (part `attach_track`: track + blade) | mounts on the host's BOTTOM (`attach_face(type) == "bottom"`): the socket is under the floor and the slide plate rides on the fin's track. `fin_len`, `fin_w`, `fin_t`. Needs a host with a floor (containers). |

**Ball joint** (`attach_joint = "ball"`, with any type): the host's socket takes a plate with a ball on a neck
(`attach_ball`); the plate of the chosen type snaps into an adapter (`attach_joint`) whose slotted cup grips the
ball and whose back has a standard socket. The host turns freely and tilts about 37° each way; pushing the lock
ring (`attach_ring`) down the tapered cup clamps it. Assembly: ring over the ball onto the neck, press the ball
into the cup, push the ring towards the adapter. The cup bends 1.4% when the ball goes in (`ball_strain()`, asserted
under 2%); the joint adds about 30 mm between host and wall. Not for heavy hosts: the neck is 8 mm.

In a project, place sockets with the host helpers (see `projects/_template/_template.scad`):

```scad
a_x = attach_xs(attach_count, width, attach_type, size=attach_size);   // x positions (fewer if they don't fit); avoid=[x, half_width] keeps clear of a zone
a_y = attach_y(0);                                      // plate centre for a host centred on y = 0
assert(attach_type == "none" || attach_fits(attach_size, height, thickness=t), attach_fit_msg(attach_size, height, t));
difference() { host(); attach_sockets(attach_type, attach_size, a_x, a_y); }
// in the parts table: each attach_rows(attach_type, len(a_x), attach_joint, opts=a_opts)
attach_all(part, attach_type, attach_size, a_x, a_y, a_opts, y_bottom, y_top, attach_joint);   // plates, track, ball joint
```

Host rules: the socket needs `attach_socket_len(size)` of height (plate + 3 mm pry notch) and `ATTACH_T` (4.5 mm) of depth, plus a floor
behind it. Its ceiling is printed as a bridge as wide as the socket (40–65 mm) when the host prints back-down;
the plate has 0.2 mm headroom. Test the fit first with `projects/attachments` (coupon + plate + key).

## LED strips

`spec = led_spec(led_strip_dims("10mm"), "shallow")` sets the cross-section; pass it to every LED module.

| Strip preset | Size used (w × t) |
|---|---|
| 5mm, 8mm | 5 × 2, 8 × 2 |
| 10mm, 12mm | 10 × 2.5, 12 × 2.5 |
| 8mm IP65, 10mm IP65 | 10 × 4.5, 12 × 4.8 (silicone coated) |
| custom | your own [w, t] |

These are typical values; strips vary by maker, so check the datasheet. The seat adds 0.3 mm play per side.
"shallow" puts the diffuser 3.5 mm above the strip; "deep" puts it 8 mm above, for less visible LED dots.

- **Joining:** a 20 mm key slides into the T-slot under both pieces.
- **Corners:** inward (inside edge, opening faces the corner), outward (wraps over an outside edge), flat (turns
  in the mounting plane: cut the strip and bridge it with an L-connector or wires there). Corners have 12 mm straight
  ends so keys fit. Matching corner diffusers come from the same sweep.
- **Diffusers:** print them in clear or natural PETG; the legs bend 0.25 mm as they click into the wall grooves.
- **Embedding:** `led_recess()` cuts a slot so a track sits flush in a host, e.g. lighting behind a scoreboard's numbers.

## Cables

Mounting parts sit on z=0 with the cable along +X; `mount="screw"` adds a countersunk M3 tab. The duct lid's
legs bend 0.25 mm over ramped beads. Host cutters work like `attach_socket()`: the host face is z=0 and its
body is z>0. `cable_route([[x,y], ...], w, d)` cuts a groove along a polyline, for example in a board's back
from an LED track to the edge.

## Logos and artwork

Check any rebuild against the original with `python3 tools/artfit.py overlay exported.svg reference.png out.png`
(prints the overlap and writes a comparison picture).

Rebuild a logo **exactly** from its SVG with `python3 tools/svg_to_scad.py art.svg lib/emblems/<name>_data.scad --path <id> --prefix XX`.
It flattens the paths (lines, cubic and quadratic curves, arcs) into OpenSCAD polygons in the SVG's px frame
(y up) and groups them into regions (an outline plus its holes, even-odd like the SVG). It prints each region's
centre and size so a small `lib/emblems/<name>.scad` can name the elements (see `bolavuit.scad`).
Don't use `import("x.svg")` for artwork: desktop OpenSCAD and the browser build scale SVGs differently
(120 mm came out as 154 mm in the browser). The polygon data has no scaling ambiguity.

`emblem.scad` holds generic, adjustable versions of the same kinds of element for new designs. Their default
shapes were measured from the Bola Vuit artwork: leaves are slender almonds (width ∝ sin(πt)^0.62, 27% of the length),
wreaths grow in groups of one inner and two outer leaves, banners are drawn as interiors plus an outline stroke.
To match another logo, fit the parameters against its exact polygons (see `projects/bolavuit_logo/README.md`).

## Fonts

`fonts/` holds Liberation Serif and Sans, regular and bold (SIL Open Font License). Bundling them means
text renders the same on every machine and in the browser configurator. The WebAssembly engine finds
no system fonts, so build text models natively (`OSCAD_ENGINE=native`) when using the skill scripts.
